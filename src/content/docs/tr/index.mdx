## Kara kutu değil, şeffaf kutu

Tipik bir derleyici yalnızca kaynak girdisini ve son çıktısını gösterir;
aradaki aşamalar gözlemlenemez. saQut her aşamayı, isimlendirilmiş ve makinece
okunabilir bir sonuç üreten ayrı bir komut olarak sunar:

```bash
saqut tokens  hello.sqt     # token akışı        (JSON)
saqut ast     hello.sqt     # soyut sözdizim ağacı (JSON)
saqut symbols hello.sqt     # sembol tablosu       (JSON)
saqut ir      hello.sqt     # 3 adresli ara kod
saqut run     hello.sqt     # derle ve çalıştır
```

Dil bilinçli olarak küçük ve C benzeri tutuldu. Amacı, incelenebilir işlem
zincirine derlenecek bir kaynak sağlamaktır.

---

## İlk programınız

<Steps>

1. `hello.sqt` adında bir dosya oluşturun:

   ```c
   int main() {
       print("Merhaba saQut!");
       return 0;
   }
   ```

2. Çalıştırın (`class` veya hazır kalıp kod gerekmez; program `main` fonksiyonundan başlar):

   ```bash
   saqut run hello.sqt
   ```

3. Merak ettiğiniz herhangi bir aşamanın **içine bakın**:

   ```bash
   saqut ast hello.sqt --json
   ```

</Steps>

[Başlangıç](/tr/getting-started/) rehberi derleyiciyi kurmayı ve daha uzun
programlar yazmayı anlatır.

## Kısa bir bakış

```c
int fibonacci(int n) {
    if (n <= 1) {
        return n;
    }
    return fibonacci(n - 1) + fibonacci(n - 2);
}

int main() {
    print(fibonacci(10));   // 55
    return 0;
}
```

Fonksiyonlar, kontrol akışı ve `print()`. Zorunlu tören kodu yok.

## saQut nasıl kuruldu

<CardGrid stagger>
  <Card title="Şeffaf işlem zinciri" icon="open-book">
    Token, AST, sembol tablosu ve ara kodun her biri isimlendirilmiş ve
    makinece okunabilir bir çıktıdır. `saqut ast` çıktısını kendi aracınıza
    yönlendirin, optimize edilmiş ağacı karşılaştırın ya da yalnızca
    `saqut symbols` çıktısından bir LSP kurun.
  </Card>
  <Card title="Prosedürel ve açık" icon="pencil">
    C ailesi sözdizimi. Nesne yönelimi yok, jenerik tip yok, gizli tip
    dönüşümü yok. `int` ile `float` karıştığında belirtilmiş tek bir kural
    geçerli. Derleyici yazdığınız şeyi çalıştırır.
  </Card>
  <Card title="Değer ve referans, işaretçi yok" icon="setting">
    Temel tipler (`int`, `float`, `bool`, `byte`) kopyalanır. Bileşik tipler
    (`string`, `struct`, `array`) referans ile paylaşılır. Programcının
    görebileceği `&` veya `*` yoktur.
  </Card>
  <Card title="Nullable isteğe bağlıdır" icon="approve-check">
    Bir değer, siz <code>T?</code> olarak bildirmedikçe null olamaz. Tip
    denetleyici, null olamaz bir değerin null olamayacağını kullanımdan önce
    doğrular; bu yüzden çalışma zamanında null denetimi yapılmaz.
  </Card>
  <Card title="Belirlenimci sanal makine" icon="random">
    Referans arka uç bir bytecode sanal makinesidir: aynı girdi her çalıştırmada
    aynı çıktıyı üretir. LLVM bilinçli olarak kullanılmaz. Deneysel bir MIR JIT
    <code>--jit</code> ile çalışır; sırada gömülü çalışma zamanlı AOT var.
  </Card>
  <Card title="Yakalanabilir hatalar" icon="error">
    <code>try</code> / <code>catch</code> / <code>throw</code> ile struct tabanlı
    hata yönetimi. Sınır aşımı, sıfıra bölme ve null referans hataları programı
    sessizce sonlandırmak yerine yakalanabilir bir hata fırlatır.
  </Card>
</CardGrid>

## İşlem zinciri, uçtan uca

```
Kaynak -> Sözcük Analizi -> Sözdizimi Analizi -> AST -> Sembol Toplama -> Tip Denetimi
  -> Optimizasyon (sabit katlama + ölü kod temizliği) -> Ara Kod -> Bytecode VM -> çıktı
```

Her ok, çalıştırıp inceleyebileceğiniz bir CLI komutuna karşılık gelir.
